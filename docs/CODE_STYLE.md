# Стандарт кода Lamnezia

Код пишется для людей, которые будут поддерживать его через год, не зная контекста. Каждое правило
ниже служит одной цели: открыть файл и быстро понять, что он делает и где его менять.

## 1. Принципы

- **Чисто и лаконично.** Меньше кода — меньше поддержки. Нет мёртвого кода, закомментированного кода,
  «на будущее» и дублирования.
- **Читаемость важнее хитрости.** Очевидное решение лучше короткого, но непонятного.
- **ООП там, где оно моделирует предметную область,** а не ради себя. Класс — это понятие проекта
  (сервер, протокол, ключ, канал уведомлений), у которого есть данные и поведение.
- **Явные зависимости.** Класс получает то, что ему нужно, через конструктор, а не берёт из глобального состояния.

## 2. Слои и где живёт логика

| Слой | Что делает | Чего не делает |
|---|---|---|
| `amnezia_core/` | Форматы Amnezia: конфиги, `clientsTable`, ключи, `vpn://` | Не знает про Django, БД и сеть |
| Модели (`models.py`) | Данные, инварианты, простые вычисляемые свойства | Не ходят по SSH, не шлют уведомления |
| Сервисы (`services/`) | Бизнес-операции: выдать ключ, применить лимит, открыть инцидент | Не знают про HTTP, шаблоны и мессенджеры |
| Views, consumers, адаптеры ботов | Принять запрос, вызвать сервис, отдать ответ | Не содержат бизнес-логики |
| Celery-задачи | Тонкая обёртка: загрузить объект → вызвать сервис | Не содержат бизнес-логики |

Веб, WebSocket, Telegram и Discord вызывают **одни и те же сервисы**. Логика не дублируется по интерфейсам.

## 3. ООП: как проектировать классы

- **Один класс — одна ответственность.** Если в названии нужно «And» или «Manager» без уточнения — класс делает слишком много.
- **Базовый класс — только при двух и более реализациях**, существующих или запланированных.
  Разрешённые точки расширения проекта:
  - `Protocol` → `AwgProtocol` (дальше `XrayProtocol`, `WireguardProtocol`) — реестр протоколов;
  - `NotificationChannel` → `EmailChannel`, `TelegramChannel`, `DiscordChannel`, `WebhookChannel`;
  - `BotAdapter` → `TelegramAdapter`, `DiscordAdapter`;
  - `PaymentProvider` → плагины оплаты.
  Новый протокол или канал добавляется **новым классом и регистрацией**, без правки существующих.
- **Композиция вместо наследования** для всего остального.
- Абстрактные методы — через `abc.ABC` / `@abstractmethod`; контракт описан в docstring базового класса.
- Объекты-значения (конфиг пира, параметры AWG, результат проверки) — `@dataclass(frozen=True)`.
- Никаких God-объектов, синглтонов и «utils.py» со всем подряд.

## 4. Оформление

- Python 3.12, **type hints везде** (проверка mypy + django-stubs в CI).
- Идентификаторы, docstring и комментарии в коде — **на английском** (международный open-source).
  Тексты интерфейса — через gettext (RU/EN), документация — RU и EN.
- Имена говорят сами за себя: `KeyIssuer.issue(user, instance)`, а не `process(data)`.
- **Docstring** — у публичных классов и неочевидных публичных методов: одна-две строки «что и зачем».
  Комментарии внутри кода — только «почему», если это не очевидно (обход бага, требование совместимости с Amnezia).
- Ориентиры размера: функция ≤ 30 строк, класс ≤ 200 строк, файл ≤ 300 строк. Больше — повод разделить.
- Ruff (`E, F, W, I, B, UP, SIM, N, C90, DJ, PL, RUF`), сложность функции ≤ 10. Форматирование — `ruff format`.
- Исключения — свои классы на каждый смысл (`SshConnectionError`, `LimitExceeded`) с человеческим
  сообщением; голый `except:` и `except Exception: pass` запрещены.
- Настройки — только через `settings` / `SiteSettings`, никаких магических чисел в коде.

## 5. Django

- Кастомный `User`, `AbstractUser`.
- Class-based views для CRUD; простые function views допустимы, если короче.
- Запросы без N+1 (`select_related`/`prefetch_related`), тяжёлые выборки — в методах QuerySet/Manager.
- Миграции — маленькие, по одной на изменение; данные мигрируются отдельной миграцией.
- Шаблоны без логики: всё вычисляется во view или в template tags.

## 6. Тесты

- На каждый сервис и каждый класс `amnezia_core` — unit-тесты. Тест читается как пример использования.
- pytest + фабрики (factory_boy), без фикстур-монстров.
- Внешний мир (SSH, мессенджеры, SMTP, GitHub) — через интерфейсы и фейковые реализации в тестах.

## 7. Документация — часть задачи

- Изменилось поведение или настройки → обновить `docs/wiki/` (RU и EN) и `CHANGELOG.md` в том же PR.
- Новый env-параметр → `.env.example` с комментарием и страница конфигурации в wiki.
- У нового модуля — docstring, первая фраза которого говорит, что в нём лежит.

## 8. Чек-лист перед коммитом

- [ ] Логика в сервисе, а не во view/задаче/адаптере.
- [ ] Нет дублирования и неиспользуемого кода.
- [ ] Новый класс оправдан (понятие предметной области или точка расширения).
- [ ] Type hints, docstring у публичного API, понятные имена.
- [ ] `ruff check`, `ruff format --check`, `mypy`, `pytest` проходят.
- [ ] Документация и CHANGELOG обновлены, если изменилось поведение.
- [ ] У новых модулей есть docstring.
