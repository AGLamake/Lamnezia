# API

API панели даёт вашему биллингу, ботам и мониторингу читать данные панели: серверы и их состояние,
пользователей с лимитами и расходом, ключи и трафик. Версия 1 только читает: ничего в панели и на
серверах через неё не меняется.

## Токены

**Система → Токены API** (`/settings/api/`, только администратор) — список токенов и создание
новых. У токена есть:

- **название** — кто им пользуется, например `monitoring`;
- **от имени кого** он действует — администратор или модератор. Токен видит то же, что этот
  человек: токен администратора — всю панель, токен модератора — только его серверы, пользователей
  и ключи;
- **область** — пока только `read`;
- необязательный **срок**.

Значение токена (`lmz_…`) показывается один раз, сразу после создания, — тогда его и скопируйте.
Панель хранит только хеш и первые символы, чтобы токены можно было различить в списке.

Токен перестаёт работать, если его отключили, если срок вышел или если владельца заблокировали или
он больше не администратор и не модератор. **Отключить** — необратимо: вместо этого создайте новый
токен.

## Запрос

Токен передаётся в заголовке `Authorization`. В адресе панель его не принимает, чтобы он не попадал
в журналы прокси:

```sh
curl -H "Authorization: Bearer lmz_..." https://panel.example.com/api/v1/servers
```

Только `GET`. Ответы — JSON, время в ISO 8601, трафик в байтах. Списки постраничные: `limit`
(по умолчанию 50, не больше 200) и `offset`; в ответе `count` (размер всего списка), `limit`,
`offset` и `results`.

Ошибки приходят как `{"error": {"code": "...", "message": "..."}}`:

| Код | `code` | Когда |
|---|---|---|
| 400 | `bad_parameter` | У параметра запроса неверное значение. |
| 401 | `token_missing`, `token_invalid` | Нет токена, он неизвестен или не работает. |
| 404 | `not_found` | Объекта нет или он вне зоны токена. |
| 405 | `method_not_allowed` | Метод не `GET`. |
| 429 | `too_many_calls` | Больше `LAMNEZIA_API_RATE_LIMIT` вызовов в минуту; подождите `Retry-After` секунд. |

## Эндпоинты

Все под `/api/v1/`:

| Путь | Что |
|---|---|
| `token` | Токен вызова: название, область, срок, владелец, `zone` (`whole` или `moderator`). |
| `servers`, `servers/<id>` | Состояние, онлайн, обслуживание, оплачен до, последний замер нагрузки, протоколы. |
| `users`, `users/<id>` | Роль, статус, тариф, действующие лимиты и расход за период и всего. |
| `keys`, `keys/<id>` | Владелец, сервер, протокол, статус, даты. Фильтры: `user`, `server`, `status`. |
| `traffic` | Трафик по часам (`period=day`) или по дням (`week`, `month`) и по ключам. Фильтры: `server`, `user`, `key`. |

Полное описание — OpenAPI 3.1 по адресу `/api/v1/openapi.json`. Токен для него не нужен: данных
панели в нём нет. Его можно загрузить в Swagger UI, Postman или генератор клиентов.

## Чего API не отдаёт никогда

SSH-доступы к серверам, ключи серверов и настройки протоколов, приватные ключи и профили клиентов,
публичный ключ ключа (у XRay это UUID клиента — сам доступ), ссылки-подписки, пароли и данные 2FA.

## Частота и аудит

Один токен делает не больше `LAMNEZIA_API_RATE_LIMIT` вызовов в минуту (по умолчанию 120, `0`
снимает ограничение, [Настройка](Configuration.md)). Вызовы с неверным токеном ограничиваются так же,
но по адресу клиента, поэтому подбирать токены бесполезно.

Каждый вызов с рабочим токеном попадает в [журнал действий](Audit.md) как **Вызов API** с началом
токена, путём и кодом ответа. Вызов отключённым или просроченным токеном — **Вызов API отключённым
токеном**. Вызовы с неизвестными токенами не пишутся, чтобы перебор не засорял журнал. Создание и
отключение токена тоже пишутся.
