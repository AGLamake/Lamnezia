# Бэкапы

Сохранять нужно три вещи:

- **базу данных** — серверы, ключи, пользователи, настройки;
- **файл `.env`** — в нём `LAMNEZIA_ENCRYPTION_KEY`. Без него сохранённые SSH-доступы и ключи клиентов
  не расшифровать, даже имея базу;
- **том `media`** — загруженные файлы (скриншоты в обращениях).

Панель хранит два вида резервных копий:

- **бэкапы панели** — база данных и том `media`, их пишет сервис `backup` из `compose.yaml`
  в `/opt/lamnezia/backups`; `.env` сохраняете вы;
- **ключи серверов** — в базе лежат ключи каждого сервера AmneziaWG 2.0 и каждого клиента, а раз в
  час панель ещё и копирует с сервера файлы каждого VPN-протокола: `awg0.conf` и `clientsTable`
  AmneziaWG 2.0, папки остальных протоколов, ключи сайта в Tor, Telegram-прокси и SFTP. По ним
  протокол или сервис ставится на новый VPS с теми же ключами.

## Бэкапы панели

Сервис `backup` запускается вместе с панелью. Сразу и затем раз в сутки он пишет два файла:

- `db-ГГГГММДД-ЧЧММСС.dump` — база данных (`pg_dump -Fc`);
- `media-ГГГГММДД-ЧЧММСС.tar.gz` — том `media`.

Время в именах — UTC. Хранятся 14 последних файлов каждого вида, старые удаляются. Файл получает
своё имя, только когда записан целиком; если бэкап не удался, прежние остаются, а ошибка — в
`docker compose logs backup`. Файлы читает только root.

Настройки в `.env`:

| Переменная | По умолчанию | Что задаёт |
|---|---|---|
| `LAMNEZIA_BACKUP_INTERVAL` | `86400` | Секунд между бэкапами. |
| `LAMNEZIA_BACKUP_KEEP` | `14` | Сколько бэкапов каждого вида хранить. |
| `LAMNEZIA_BACKUP_DIR` | `./backups` | Каталог для бэкапов на хосте. |

После изменения выполните `docker compose up -d backup`. Бэкап прямо сейчас:

```bash
docker compose run --rm backup sh /usr/local/bin/backup.sh once
```

**Сохраните `.env` отдельно** — один раз и после каждого изменения: в нём `LAMNEZIA_ENCRYPTION_KEY`.
В бэкапы он намеренно не входит. Без него SSH-доступы и ключи в базе не расшифровать.

Бэкапы на той же машине не переживут её потерю. Копируйте каталог в другое место, например
по cron с другого сервера:

```bash
rsync -a root@panel.example.com:/opt/lamnezia/backups/ /srv/lamnezia-backups/
```

## Восстановление панели

Восстанавливайте на сервере, где панель ещё не запускалась: пароль PostgreSQL задаётся при первом
старте базы и должен совпасть с тем, что в сохранённом `.env`.

```bash
git clone https://github.com/AGLamake/Lamnezia.git /opt/lamnezia
cd /opt/lamnezia
cp /root/lamnezia.env .env && chmod 600 .env
docker compose up -d --wait postgres
docker compose exec -T postgres pg_restore -U lamnezia -d lamnezia --no-owner < /root/backups/db-20260101-030000.dump
docker compose run --rm --no-deps --user root -v /root/backups:/backups web \
    tar -xzf /backups/media-20260101-030000.tar.gz -C /app
docker compose up -d --build
```

Здесь `/root/lamnezia.env` — сохранённый `.env`, а в `/root/backups` — скопированные бэкапы; берите
самую свежую пару файлов. Пока панели нет, VPN-серверы продолжают работать. Если потерян и
VPN-сервер, восстановите его после панели: [восстановление протокола](#восстановление-протокола-на-новом-vps).

Затем настройте HTTPS: запустите `install.sh` (он оставит восстановленный `.env`) или выполните
[Установку, раздел 5](Installation.md#5-установка-вручную). Если сменился домен — исправьте
`LAMNEZIA_DOMAIN` в `.env`; если порт `LAMNEZIA_HTTP_BIND` на новом сервере занят — выберите другой.

## Копии файлов серверов

Каждые `LAMNEZIA_PROTOCOL_BACKUP_INTERVAL` секунд (по умолчанию час) панель читает `awg0.conf` и
`clientsTable` каждого сервера AmneziaWG 2.0 и хранит их в базе зашифрованными. Копия только
читается, на сервере ничего не меняется. Сервер, который не ответил, сохраняет прошлую копию.
Не заменяет её и сервер, где AmneziaWG теперь работает с другим ключом сервера: его файлы не те,
которым принадлежат ключи панели.

У остальных VPN-протоколов панель копирует папки, где контейнер хранит своё состояние, как есть —
архивом `tar.gz`:

| Протокол | Папки | Что в них |
|---|---|---|
| AmneziaWG legacy (`amnezia-awg`) | `/opt/amnezia/awg` | `wg0.conf`, preshared key, `clientsTable` |
| WireGuard (`amnezia-wireguard`) | `/opt/amnezia/wireguard` | `wg0.conf`, preshared key, `clientsTable` |
| OpenVPN (`amnezia-openvpn`) | `/opt/amnezia/openvpn` | CA easy-rsa, `index.txt`, список отзыва, `server.conf` |
| XRay (`amnezia-xray`) | `/opt/amnezia/xray` | `server.json`, ключи Reality, `clientsTable` |
| IPsec (`amnezia-ipsec`) | `/etc/ipsec.d`, `/opt/amnezia/ikev2` | база NSS с CA и сертификатами |

Копия снимается, только если файлы относятся к ключу сервера, который есть в панели: приватному
ключу WireGuard и XRay, CA у OpenVPN и IPsec.

У сервисов панель копирует то, по чему их знают пользователи:

| Сервис | Папки | Что в них |
|---|---|---|
| Сайт в Tor (`amnezia-torwebsite`) | `/var/lib/tor/hidden_service`, `/var/www/html/wp-content`, `wp-config.php`, `.htaccess` | ключи onion-адреса, сайт WordPress и дамп его базы |
| MTProxy (`amnezia-mtproxy`) | `/data` | секрет ссылок и настройки установки |
| Telemt (`amnezia-telemt`) | `/data` | секрет, `config.toml` с настройками и переключателями |
| SFTP (`amnezia-sftp`) | `/etc/ssh`, `/home` | SSH-ключи хоста и загруженные файлы |

Копия сервиса снимается, только пока его контейнер работает с тем, что есть в панели: тем же
onion-адресом, секретом прокси или логином и паролем SFTP. Копия сайта в Tor и SFTP может быть до
256 МБ в распакованном виде (у остальных до 64 МБ); бо́льшая не снимается, остаётся прошлая. Ядро
WordPress не копируется — его приносит образ. У SOCKS5 нечего хранить (логин и пароль есть в
панели), у DNS-сервиса нет состояния.

**Новый секрет прокси сразу попадает в копию.** **Новый секрет** или новые настройки
Telegram-прокси просят копию сервиса сразу после операции: в старой копии старый секрет, по
которому панель прокси уже не знает.

**Только что выданные ключи тоже попадают в копию.** Кроме часовой копии, выдача, отключение,
включение или отзыв ключа просят ещё одну копию его протокола примерно через 30 секунд; операции с
ключами за эти 30 секунд попадают в одну копию. Если сервер в этот момент не отвечает, остаётся
прошлая копия, а следующая часовая её догонит.

**Удаление сервера не удаляет его копии.** Сервер, у протоколов или сервисов которого есть копии,
одним действием не удаляется — панель откажет. Сначала удалите его протоколы и сервисы (у протокола
— с отметкой **Удалить все бэкапы?**), затем сервер.

Раздел **Резервная копия** на странице сервера показывает, когда снята последняя копия. У
протокола, кроме AmneziaWG 2.0, и у сервиса кнопка **Восстановить на этом сервере** есть, только
когда есть копия.

Удаление контейнера на странице сервера сохраняет копию и ключи, если не отмечено **Удалить все
бэкапы?** ([Протоколы](Protocols.md#контейнер-перезапуск-остановка-лог-удаление)). Прямо перед
удалением контейнера панель снимает свежую копию его файлов; если не вышло — остаётся прошлая, а
журнал операции об этом пишет. Протокол тогда помечен **контейнер удалён**, больше не
опрашивается, а **Восстановить на этом сервере** возвращает его с теми же клиентами.

Диалог удаления предупреждает, если у протокола, кроме AmneziaWG 2.0, копии ещё нет: если не
выйдет и копия перед удалением, его ключи больше не заработают, даже после новой установки.

## Восстановление протокола на новом VPS

Если VPN-сервер потерян, его протокол ставится на новый VPS со старыми ключами: прежние приватный
ключ сервера, preshared key, порт и параметры AWG, у каждого клиента — его адрес.

1. Создайте VPS с Debian или Ubuntu, как для нового сервера ([Серверы и импорт](Servers-and-import.md)).
2. Если адрес меняется, направьте DNS-имя сервера на новый VPS. **Клиенты работают без изменений,
   только если адрес в их конфигах прежний** — тот же IP или то же DNS-имя, если сервер добавлен по
   имени. Иначе сервер заработает, но клиентам нужны новые ключи из портала.
3. Откройте страницу сервера и нажмите **Изменить**: укажите новый адрес и логин. Отпечаток
   старого адреса забудется сам. У нового VPS со старым адресом другой SSH-ключ хоста: нажмите
   **Забыть** рядом с отпечатком SSH на странице сервера, иначе панель откажется подключаться.
4. В разделе **Резервная копия** нажмите **Восстановить на этом сервере**. Операция подготовит
   сервер, соберёт контейнер и запишет файлы; ход виден на странице сервера.
5. Проверьте: проверка сервера проходит, клиент подключается со старым конфигом.

Что записывает восстановление:

- последнюю копию файлов сервера, сверенную с ключами панели: активные ключи, выданные после копии,
  добавляются, отключённые убираются из `awg0.conf` (имя остаётся в `clientsTable`), отозванные
  удаляются; клиенты, добавленные в приложении Amnezia и попавшие в копию, остаются;
- без копии — настройки сервера из панели и активные ключи с их адресами;
- активный ключ без адреса пропускается и называется в журнале операции.

Восстановление можно запустить повторно: контейнер с тем же ключом сервера сохраняется. Сервер, где
AmneziaWG 2.0 работает с другим ключом, никогда не перезаписывается — удалите там контейнер
`amnezia-awg2` или восстановите на другой VPS.

### Остальные протоколы

AmneziaWG legacy, WireGuard, OpenVPN, XRay и IPsec восстанавливаются из копии своих папок.
Операция собирает контейнер, как при новой установке, кладёт сохранённые файлы до его настройки, а
скрипты установки приложения их оставляют: новые ключи сервера, CA и ключи Reality не создаются,
и старые конфиги клиентов снова работают. Без копии эти протоколы не восстанавливаются.

- Сначала проверяется копия: в ней должен быть ключ сервера, который есть в панели для протокола.
- Контейнер, который уже есть на сервере, проверяется **до запуска**: контейнер с ключами панели
  сохраняется, с другими ключами — остаётся как есть (не запускается, не настраивается и не
  перезаписывается), а операция останавливается. Удалите этот контейнер или восстановите на другой
  VPS.
- Ключей, выданных после последней копии, в ней нет (копия снимается примерно через 30 секунд
  после изменения ключей, так что это бывает, только если сервер потерян именно тогда): их число —
  в журнале операции, перевыпустите их.
- Сертификат сервера IPsec называет IP сервера. На VPS с другим IP перевыпустите его после
  восстановления: **Перевыпустить** в строке **Сертификат сервера IPsec** на карточке сервера
  ([Серверы](Servers-and-import.md#новый-адрес-сервера)); раздел резервной копии напоминает об
  этом.

### Сервисы

Сайт в Tor, MTProxy, Telemt и SFTP восстанавливаются из копии кнопкой **Восстановить на этом
сервере** в разделе **Резервная копия**: сервис получает прежний onion-адрес, прежние ссылки прокси,
прежние SSH-ключи хоста SFTP (клиенты не видят предупреждения о смене ключа хоста). В копии должно
быть то, что панель хранит для сервиса; контейнер с другими ключами, уже стоящий на сервере, не
запускается, и операция останавливается. Tor и sshd при старте контейнера делают свои ключи:
восстановление заменяет их копией и перезапускает контейнер. Сайт в Tor возвращается со
страницами, загрузками и базой, SFTP — с файлами своей учётной записи.

Восстановление, прерванное на полпути (связь пропала, пока клались файлы), оставляет контейнер со
своими ключами. Панель помечает такой контейнер, и повторное **Восстановить** удаляет его и ставит
сервис заново, а не отказывает. Контейнер, оставленный не так, по-прежнему не перезаписывается.

## Полное восстановление

Если потеряны и панель, и VPN-сервер:

1. Восстановите панель из бэкапа и сохранённого `.env`
   ([Восстановление панели](#восстановление-панели)).
2. Для каждого потерянного VPN-сервера выполните
   [восстановление протокола](#восстановление-протокола-на-новом-vps).
3. Откройте **Ключи → Расхождения с серверами → Проверить сейчас**: если панель и серверы ещё
   расходятся, расхождения будут там ([Ключи](Keys.md#расхождения-с-серверами)).
