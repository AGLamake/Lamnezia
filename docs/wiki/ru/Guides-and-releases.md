# Инструкции и релизы

Что видят пользователи до получения ключа: инструкции по установке для каждой платформы, загрузки
приложения Amnezia из последнего релиза, FAQ и подборка полезных материалов.

## Инструкции по установке

Страница `/guides/` показывает платформы: Windows, macOS, Linux, Android и iOS. Устройство
посетителя определяется по браузеру и отмечено как «ваше устройство».

На странице платформы (`/guides/windows/`, `/guides/android/` и т. д.) — кнопки загрузки из
последнего релиза Amnezia на GitHub, ссылка на все загрузки и три шага: установить приложение,
получить ключ, добавить его в Amnezia. Про кэш релизов и токен GitHub — в разделе
[Загрузки приложения Amnezia](#загрузки-приложения-amnezia).

- **Android.** Можно выбрать версию Android (9–10 или 11+) и процессор. По умолчанию — Android 11+
  и `arm64-v8a`, это подходит большинству телефонов. Версия берётся из браузера, если он её сообщает
  (Chrome всегда пишет «Android 10», поэтому для него остаётся 11+). Рядом — ссылка на Google Play.
- **iOS.** Приложение есть только в App Store, страница ведёт туда.
- Пока панель ещё ни разу не получила релиз (сразу после установки или без доступа к GitHub),
  страница предлагает открыть страницу релизов на GitHub.

Ссылку на выбранный APK можно отправить человеку: `/guides/android/?android=9-10&abi=armeabi-v7a`.

## FAQ

Список вопросов — `/guides/faq/`, статья — `/guides/faq/<адрес>/`.

Статьи редактируются в админке Django: **Guides → FAQ articles**.

Начальный набор статей (установка на каждую платформу, добавление ключа, «не подключается»,
«протокол заблокирован», «порт ниже 10000», «нет интернета», «медленно», «медленная выгрузка через
VPN», «ключ не добавляется», обновление приложения) встроен в панель: он появляется при первом
запуске, см. [Встроенные статьи](#встроенные-статьи).

- Текст пишется в Markdown: заголовки `##`, списки, ссылки, жирный, код.
  HTML внутри текста вырезается. Кнопка **Предпросмотр** под каждым текстом показывает его так,
  как его увидит посетитель, ничего не сохраняя.
- У статьи два языка. Если для языка посетителя заголовок или текст пустые, показывается другой язык.
  Достаточно заполнить один.
- Порядок в списке задаёт поле «position» (меньше — выше), снятая галочка «published» прячет статью.
- «Адрес» (slug) — часть ссылки на статью; заполняется по английскому заголовку, его можно поправить.

## Полезные материалы

Страница `/guides/materials/` — подборка статей с других сайтов по темам: установка, скорость,
блокировки, безопасность, устройства. Текст чужих статей не копируется: у каждого материала только
название, ссылка, язык, источник и наше краткое описание на русском и английском.

Материалы редактируются в админке Django: **Guides → Useful materials**. Начальная подборка
(документация Amnezia, разборы AmneziaWG и обхода блокировок, настройка устройств, диагностика
скорости) встроена в панель, как и FAQ.

### Встроенные статьи

При каждом запуске, сразу после миграций, контейнер `web` выполняет `manage.py load_guides`. Команда
добавляет встроенные статьи FAQ и полезные материалы, которых в этой панели ещё не было; записи
сопоставляются по адресу (slug):

- на новой установке весь набор появляется при первом запуске;
- после обновления добавляются статьи, новые в этой версии;
- изменённые вами статьи остаются как есть, а удалённые не возвращаются: панель помнит каждый
  встроенный адрес, который уже предлагала;
- повторные перезапуски ничего не дублируют.

Удалённые встроенные записи собраны в админке в разделе **Guides → Built-in entries**. Отметьте их
и выберите действие **Вернуть выбранные записи**: они вернутся с текстом текущей версии. Запись,
чей адрес снова занят или которой в этой версии больше нет, пропускается.

Чтобы вернуть исходный текст изменённой встроенной статьи, загрузите весь набор вручную: команда перезапишет
встроенные статьи по адресу и не тронет добавленные вами:

```bash
docker compose exec web python manage.py loaddata faq materials
```

Раз в неделю фоновая задача (`beat`, `guides.check_materials`) открывает каждую опубликованную
ссылку. Ссылка, которая не открылась (ошибка HTTP, сайт недоступен), помечается **«битая
ссылка»** с текстом ошибки и пропадает с публичной страницы. В админке такие ссылки видны в
фильтре «битая ссылка»; там же дата последней проверки. Исправьте или замените ссылку — при
следующей проверке пометка снимется сама. Пока такие ссылки есть, дашборд администратора
показывает, сколько опубликованных материалов скрыто, со ссылкой на отфильтрованный список.
Проверка ходит только по ссылкам из подборки, ничего о
посетителях не записывает.

## Предложения пользователей

Вошедший пользователь открывает **Инструкции → Предложить статью** (`/guides/suggest/`) и
присылает ссылку на статью или свой текст в Markdown, с языком, темой и комментарием для
персонала. Галочка решает, указывать ли его имя при публикации. Под формой пользователь видит
свои прошлые предложения, что с ними стало и причину отказа.

- Аноним предлагать не может: страница отправляет его на вход.
- Пользователь присылает не больше `LAMNEZIA_SUGGESTION_RATE_LIMIT` предложений в сутки (по
  умолчанию 3, `0` снимает ограничение).
- Принимаются только ссылки `http://` и `https://`. Markdown проходит ту же очистку, что и статьи
  FAQ: HTML, скрипты и ссылки `javascript:` вырезаются.
- **Настройки → Пользователи и ключи → Пользователи предлагают статьи** выключает форму;
  страница тогда пишет, что предложения не принимаются.

Администраторы и модераторы разбирают предложения в разделе **Предложения статей** меню
администратора (`/guides/moderation/`). На странице предложения — оно в том виде, как прислал
автор (текст показан так, как будет выглядеть), и форма, где его можно поправить перед
публикацией:

- ссылка становится **полезным материалом** (допишите наше описание и источник);
- текст становится **статьёй FAQ** на своём языке.

**«Опубликовать как»** переключает форму на другой вид: ссылку можно опубликовать статьёй FAQ (в
тексте сначала стоит сама ссылка), текст — полезным материалом (текст становится описанием,
ссылку укажите). Переключайте до правки: форма заполняется заново из предложения.

Поле **«Предложил»** содержит имя автора, если он просил его указать, иначе пусто; оно
показывается под материалом или статьёй и его можно поправить. Для **«Отклонить»** нужна
причина. Автор получает уведомление о любом решении там, где он получает уведомления
(`suggestion_accepted` со ссылкой, `suggestion_rejected` с причиной; см.
[Уведомления](Notifications.md)). Новое предложение — событие `suggestion_created` для каналов
персонала. Оба решения записываются в журнал действий.

## Загрузки приложения Amnezia

Ссылки на загрузку берутся из последнего релиза `amnezia-vpn/amnezia-client` на GitHub. Его
раз в 6 часов запрашивает фоновая задача (`beat`) и сохраняет в базу; страницы инструкций сами в
GitHub не ходят и читают сохранённый релиз. Если базы релиза ещё нет, первая открытая страница
ставит задачу на обновление. Если GitHub недоступен, остаётся последний полученный релиз.
Без токена GitHub даёт 60 запросов в час с одного IP — для одной панели этого хватает.
