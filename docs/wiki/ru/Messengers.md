# Аккаунты Telegram и Discord

Пользователь привязывает свои Telegram и Discord в разделе **Мессенджеры**
**Профиля** (`/accounts/profile/#messengers`). Можно привязать один или оба. Один
аккаунт Telegram или Discord принадлежит одному пользователю панели: аккаунт, привязанный к
кому-то другому, не привяжется, пока тот его не отвяжет.

## Настройка

По шагам, с BotFather и Discord Developer Portal: [Настройка ботов](Bots.md).

В **Настройки → Интеграции** (администраторы):

| Поле | Для чего |
|---|---|
| Токен Telegram-бота, имя Telegram-бота | Привязка Telegram: бот открывается с одноразовым кодом. Имя без `@`. |
| ID приложения Discord, секрет клиента Discord | Привязка Discord через OAuth2. В Discord Developer Portal добавьте redirect, показанный под полями (`<адрес панели>/accounts/discord/callback/`). |
| Токен Discord-бота | Discord-бот: ключи, меню и уведомления в личные сообщения. Страница **Bot** того же приложения в Developer Portal. |
| Вход через Telegram | Выключен по умолчанию. Показывает кнопку **Войти через Telegram** на странице входа. Кнопка открывает страницу входа самого Telegram (`oauth.telegram.org`), которая возвращает посетителя в панель; панель проверяет подпись Telegram. Отправьте `/setdomain` боту @BotFather с доменом панели (он показан под опцией), иначе Telegram ответит «Bot domain invalid». |
| Вход через Discord | Выключен по умолчанию. Показывает кнопку **Войти через Discord** на странице входа. |

Кнопки входа — в цветах мессенджеров, с их логотипами.

### Предложение привязать

Пока у пользователя нет привязанных мессенджеров, а хотя бы один бот настроен, страница
**Мой доступ** начинается с карточки, которая предлагает привязать Telegram или Discord: входить в
одно нажатие, получать ключи и уведомления (конец доступа, лимит, ответы поддержки) и управлять
ключами прямо в мессенджере. Её кнопки сразу начинают привязку; та же карточка открывается в
чате поддержки. **Не сейчас** скрывает её на 30 дней, во второй раз — насовсем. Письмо с
подтверждением почты нового аккаунта тоже говорит, что мессенджеры можно привязать в профиле.

## Привязка

- **Telegram.** **Привязать** даёт ссылку `t.me/<бот>?start=<код>`. Бот принимает код и привязывает
  аккаунт Telegram, который нажал **Старт**.
- **Discord.** **Привязать** открывает Discord, который просит доступ только к имени аккаунта
  (scope `identify`). **Код для бота** вместо этого даёт команду `/link <код>` для бота панели.

Код работает один раз и 10 минут; новый код отменяет предыдущий. В базе хранится только его
SHA-256. **Отвязать** удаляет привязку; в ботах будет такая же команда.

### Администратором

В карточке пользователя в разделе **Пользователи** (`/users/<id>/`, администраторы) есть блок
**Привязанные аккаунты** по каждому мессенджеру: имя, ID и когда привязан, и **Отвязать** после
подтверждения. Для непривязанного мессенджера администратор может:

- ввести ID аккаунта (ID пользователя Telegram или Discord, только цифры) и при желании имя и нажать
  **Привязать**; аккаунт, привязанный к другому пользователю, не примется;
- нажать **Ссылка для пользователя**: в карточке появится одноразовая ссылка `t.me` или команда
  `/link <код>`, которую нужно переслать пользователю. Это тот же код, что в профиле, с теми же
  правилами.

В списке **Пользователи** привязанные аккаунты видны в колонке **Мессенджеры**. Фильтр
**Мессенджер** оставляет пользователей с Telegram, с Discord или без привязок, а поиск находит и
имя в мессенджере (с `@` или без), и точный ID аккаунта.

## Вход

Вход через мессенджер работает только для аккаунтов, уже привязанных к пользователю; новых
аккаунтов он не создаёт. Двухфакторная аутентификация после него всё равно спрашивает код. Ответ
Telegram старше 10 минут не принимается.

## Боты

Боты панели отвечают только привязанным аккаунтам: остальным — только как привязаться.
Пользователь, ждущий одобрения или заблокированный, видит свой статус и инструкции. Боты отвечают
на языке мессенджера пользователя (русский или английский) и принимают не больше
`LAMNEZIA_BOT_RATE_LIMIT` команд в минуту от одного аккаунта; кнопка, нажатая сверх лимита,
показывает короткое всплывающее сообщение, а панель не меняется.

| Команда | Что делает |
|---|---|
| `/start`, `/menu` | Меню с кнопками. |
| `/status` | Трафик, общий лимит и срок доступа, как на портале. |
| `/keys` | Ключи пользователя; в карточке ключа его можно показать, перевыпустить или удалить. |
| `/newkey` | Новый ключ по шагам: сервер (если в тарифе их несколько), затем устройство. |
| `/sub` | Ссылка-подписка для клиентов XRay; **Новая ссылка** заменяет её (старая перестаёт работать). Только при политике «показывать в любое время». |
| `/servers` | Состояние серверов тарифа. |
| `/down` | «Не работает сервер»: сервер, затем комментарий или без него. Панель проверяет сервер, администраторы получают обращение, как с портала. |
| `/support` | Любое сообщение не в ответ на вопрос бота уходит в чат поддержки пользователя. |
| `/ticket` | Новое обращение по шагам: тип, затем описание; его первая строка — тема. «Сервер не работает» ведёт в `/down`. |
| `/requests` | Последние обращения пользователя со статусом; в обращении видны последние сообщения и можно ответить. |
| `/guides` | Ссылки на приложение и инструкцию для каждого устройства. |
| `/unlink` | Отвязывает аккаунт после подтверждения. |

Бот общается через одно сообщение-панель. Кнопка перерисовывает это сообщение на месте: у каждого
раздела заголовок жирным, короткий текст или список, свои кнопки, а в конце «Назад» (в раздел выше)
и «Меню». Набранный текст, команда, а также уведомление или ответ поддержки, пришедшие после панели,
открывают новую панель внизу чата. Ключ (ссылка `vpn://`, QR-коды, файл `.conf`) и другие файлы
приходят отдельными сообщениями, а новая панель — под ними, поэтому дальнейшие переходы по меню ключ
не стирают. У панели, кнопка которой выдала ключ, кнопки убираются: живой остаётся только панель
ниже. Кнопки старой панели по-прежнему работают и перерисовывают её; если её уже нельзя изменить,
бот присылает новую. Панель длиннее одного сообщения мессенджера приходит несколькими сообщениями,
кнопки — под последним.

Мессенджеры принимают на кнопках только интернет-адреса. Если `LAMNEZIA_SITE_URL` — не публичный
домен (`localhost`, частный IP-адрес, имя без точки или на `.local`, `.lan`, `.internal`), ссылки на
сайт приходят строками текста вместо кнопок, так что боты работают и в dev.

Перевыпуск и удаление спрашивают подтверждение; повторное нажатие, пока старый ключ отзывается,
ничего не делает. **Ключи в ботах** (**Настройки → Пользователи и ключи**) решает, что бот показывает: сам ключ
(ссылку `vpn://`, QR-коды и файл `.conf`, только в личном чате) или только ссылку на ключ на
портале. Telegram и Discord хранят чаты на своих серверах без сквозного шифрования; выберите
ссылку, чтобы ключи туда не попадали. Со ссылкой ключ не считается показанным; иначе правило
«только один раз» тратит тот, кто покажет ключ первым, — бот или портал.

Панель помнит, из какого мессенджера пришло каждое сообщение в поддержку. Ответ сотрудника уходит туда же от бота, даже если панель у пользователя открыта: на ответ в чате можно ответить, просто написав боту, ответ на обращение подсказывает `/requests`. Картинку из ответа видно только в личном кабинете. Пользователь тоже может прислать картинку (фото в Telegram, изображение во вложении в Discord) с подписью или без: она уходит в чат поддержки или, после «Ответить», в обращение и проверяется так же, как вложение на портале. Если пользователь не ответил и не прочитал ответ за 2 минуты, туда, что он выбрал для уведомлений, приходит одно напоминание со ссылкой на переписку — если сам ответ пришёл не туда же ([Уведомления](Notifications.md)).

В журнал пишется каждая команда привязанного пользователя — только её имя, без аргументов и
текста сообщений ([Журнал действий](Audit.md)).

Боты работают в сервисе `bots` в compose; он запущен всегда, вместе с панелью.

### Блок «Боты»

В **Настройках** под формой администратору виден блок **Боты**. Он обновляется сам каждые несколько
секунд и показывает каждого бота:

- состояние: **работает** (и сколько времени), **выключен**, **нет токена**, **запускается** или
  **ошибка** с причиной (токен в ней не показывается); упавший бот запускается снова через минуту
  или сразу по кнопке **Перезапустить**;
- **не отвечает** — сервис `bots` давно не присылал отчёт: контейнер остановлен или не достучался
  до базы;
- имя бота (`@username`) и сколько пользователей привязали этот мессенджер;
- для Discord — серверы, на которых состоит бот, с числом участников и кнопкой **Покинуть** у каждого.

**Выключить** и **Включить** сохраняют выбор и после перезапусков; бот с токеном по умолчанию
включён. **Перезапустить** переподключает бота. Новый токен бот подхватывает сам за несколько
секунд, даже если у панели и сервиса `bots` нет общего кэша. Панель только записывает просьбу в базу, а выполняет её сервис `bots`; каждое действие
попадает в [журнал](Audit.md) (`bots.turn_on`, `bots.turn_off`, `bots.restart`, `bots.leave`).

### Discord-бот

Пригласите бота на сервер со scope `bot` и `applications.commands` (OAuth2 → URL Generator в
Developer Portal); прав на сервере и привилегированных intents ему не нужно. Команды меню — это
slash-команды (`/menu`, `/keys`, `/newkey`…) с описаниями на русском и английском, а `/link <код>`
привязывает аккаунт кодом из профиля. Кнопки выполняют те же действия, что в Telegram, и работают
после перезапуска бота.

С ботом работают в личных сообщениях: там ответы — обычные сообщения, а набранный текст идёт в шаги
диалога и поддержку. На сервере доступны только `/menu` и `/link`: бот открывает панель в личных
сообщениях, а на сервере отвечает эфемерной заметкой «Написал вам в личные сообщения», которую видит
только вызвавший команду. Остальным участникам сервера ничего не видно, и ключ никогда не попадает в
канал; обычные сообщения на серверах бот не читает. Если личные сообщения закрыты, бот эфемерно
подскажет, как их открыть: меню сервера → «Настройки конфиденциальности» → разрешить личные
сообщения от участников сервера, затем повторить команду. Ключ приходит как ссылка `vpn://` в блоке
кода и сообщение с QR-кодом и файлом `.conf` во вложениях, под ними — панель.
После первого запуска бота Discord может
показать команды не сразу.

### Telegram-бот

Бот отвечает только в личных чатах и не реагирует в группах, чтобы ключ туда не попал. Ключ приходит
ссылкой `vpn://` моноширинным текстом (копируется нажатием), QR-код — фотографией, файл `.conf` —
документом, под ними — панель. Меню команд бот выставляет на русском и английском.

По умолчанию бот получает обновления через long polling: работает за NAT и без домена. При
публичном домене с HTTPS задайте `LAMNEZIA_TELEGRAM_WEBHOOK=true`: Telegram будет присылать
обновления на `<LAMNEZIA_SITE_URL>/bots/telegram/` с секретным заголовком, а бот сам выставит
webhook при запуске.

- **Caddy** (`--profile caddy`) уже передаёт `/bots/telegram/` сервису `bots`.
- **nginx на хосте**: добавьте блок `location /bots/telegram/` из `deploy/nginx/lamnezia.conf`
  и опубликуйте порт сервиса `bots` в `compose.override.yaml` рядом с `compose.yaml` (если 8081
  занят, возьмите другой порт хоста и его же укажите в nginx):

  ```yaml
  services:
    bots:
      ports:
        - "127.0.0.1:8081:8081"
  ```

Чтобы вернуться к polling, задайте `false` и выполните `docker compose up -d bots` — бот сам снимет
webhook.

## Уведомления

**Мои уведомления** на той же странице выбирает, куда приходят уведомления самого пользователя:
email или привязанный мессенджер. Пишет бот панели: в Telegram — в личный чат, в Discord — в личные
сообщения (у пользователя должен быть общий сервер с ботом), с кнопкой «Меню», открывающей панель.
Без токена бота приходят письма. При отвязке мессенджера выбор
возвращается на email. См. [Уведомления](Notifications.md).

Привязка, отвязка и каждый вход через мессенджер записываются в журнал ([Журнал действий](Audit.md)).
