# Решение проблем

Логи всех сервисов: `docker compose logs -f` (одного сервиса: `docker compose logs -f web`).
Перезапуск: `docker compose restart`. Всё, что панель делала на сервере, есть в **Операциях**:
шаги, лог и, для упавшей операции, что делать дальше.

## Установка и доступ

| Признак | Что проверить |
|---|---|
| certbot: `Challenge failed`, `NXDOMAIN` | DNS ещё не указывает на сервер (`dig +short <домен>`) или порт 80 закрыт файрволом |
| `502 Bad Gateway` от nginx | Панель не запущена или порт не совпадает: `docker compose ps`, `docker compose logs web`, `LAMNEZIA_HTTP_BIND` и `proxy_pass` в сайте nginx |
| `Bad Request (400)` | Панель открыта не по `LAMNEZIA_DOMAIN`: домен в `.env` и в адресной строке должны совпадать |
| Ошибка CSRF при входе | В сайте nginx нет `proxy_set_header X-Forwarded-Proto $scheme;` |
| Не обновляется прогресс операций, не работает чат | WebSocket не проходит: в сайте nginx нужны заголовки `Upgrade` и `Connection` (они есть в `deploy/nginx/lamnezia.conf`) |
| `Set the LAMNEZIA_ENCRYPTION_KEY environment variable` | В `.env` не задан ключ шифрования ([Установка](Installation.md#5-установка-вручную)) |
| `port is already allocated` | Порт из `LAMNEZIA_HTTP_BIND` занят другим сервисом — выберите другой |
| `web` не становится `healthy`, в логах `password authentication failed` | `LAMNEZIA_DB_PASSWORD` изменён после первого запуска; верните прежний пароль |

## FAQ для администратора

**Администратор потерял телефон с аутентификатором.**
`docker compose exec web python manage.py reset_2fa <имя>`, затем войдите и подключите приложение
заново ([Безопасность](Security.md#двухфакторный-вход)).

**При входе пишет, что учётная запись заблокирована.**
Слишком много неверных паролей с одного адреса. Подождите `LAMNEZIA_LOGIN_LOCKOUT_MINUTES` минут
или удалите запись в `/admin/` → **Access attempts**.

**Не приходят письма (сброс пароля, подтверждение, уведомления).**
Пока в **Настройках** не задан SMTP-сервер и не задан `LAMNEZIA_EMAIL_URL`, письма только пишутся
в лог: `docker compose logs web`. После настройки почты отправьте тест из канала в **Уведомлениях**.

**Проверка сервера падает с ошибкой ключа хоста.**
Сервер переустановлен или соединение перехвачено. Если переустанавливали вы, удалите старую запись
в `/admin/` → **Ssh → Known hosts** и проверьте сервер снова.

**Проверка сервера пишет, что вход отклонён или sudo требует пароль.**
Проверьте пользователя, ключ или пароль и что пользователь — `root` или у него есть `NOPASSWD` в
sudoers ([Серверы и импорт](Servers-and-import.md#добавление-сервера)).

**Операция висит в «ожидании» или «выполняется».**
Другая операция держит блокировку того же сервера или остановился `worker`:
`docker compose ps worker`, `docker compose logs worker`. Через `LAMNEZIA_OPERATION_TIMEOUT`
операция помечается прерванной, её можно повторить кнопкой **Повторить**.

**Сервер показан недоступным, хотя работает.**
Панель опрашивает его каждые `LAMNEZIA_MONITOR_INTERVAL` секунд; на странице сервера видна
последняя ошибка. Обычно SSH закрыт файрволом или сменился порт SSH.

**Ключей, созданных в приложении Amnezia, нет в панели.**
Панель сверяет ключи с серверами каждые `LAMNEZIA_RECONCILE_INTERVAL` секунд. Откройте
**Ключи → Расхождения с серверами → Проверить сейчас** и **Добавить в панель**
([Ключи](Keys.md#расхождения-с-серверами)).

**Ключи пользователя выключились сами.**
Достигнут лимит или кончился срок доступа: статус ключа «отключён по лимиту». Продлите доступ или
поднимите лимит, и ключи включатся при следующей проверке
([Пользователи, тарифы и лимиты](Users-plans-limits.md#применение-лимитов)).

**Изменение протокола останавливается с подсказкой про `amnezia-awg2-previous`.**
Прошлая смена порта была прервана. Сравните контейнеры в `docker ps -a` на сервере и удалите
ненужный ([Протоколы](Protocols.md#параметры-протокола)).

**Лог контейнера пустой.**
У контейнеров, запущенных приложением Amnezia, логирование выключено. Отметьте **Вести лог
контейнера** в параметрах протокола ([Протоколы](Protocols.md#контейнер-перезапуск-остановка-лог-удаление)).

**Пользователи видят «сервер недоступен», хотя он работает.**
Порт пробы доступности может быть закрыт у хостера, или сеть пользователя действительно блокирует
UDP ([Серверы и импорт](Servers-and-import.md#проверка-доступности)).

**В инструкциях нет кнопок загрузки Amnezia.**
GitHub недоступен, и релиз ещё ни разу не получен; задайте `LAMNEZIA_GITHUB_TOKEN`, если упёрлись
в лимит API ([Инструкции и релизы](Guides-and-releases.md#загрузки-приложения-amnezia)).

**Отдача через VPN в разы медленнее скачивания.**
Интерфейс контейнера склеивает TCP-пакеты (TSO/GSO). Нажмите **Проверить** в блоке **Скорость
отдачи через VPN (TSO/GSO)** на странице сервера; если TSO или GSO `on`, нажмите **Включить**
([Протоколы](Protocols.md#обход-tsogso)).

**VPN-сервер потерян.**
Восстановите протокол на новом VPS с теми же ключами ([Бэкапы](Backup.md#восстановление-протокола-на-новом-vps)).
