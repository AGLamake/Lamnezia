# Уведомления

**Админка → Уведомления** (`/notifications/`, только администраторы) отправляет события панели на
почту, в Telegram, Discord и в ваши вебхуки.

## Каналы

Канал — одно место, куда приходят сообщения. Каналов каждого вида может быть несколько.

| Вид | Что заполнить |
|---|---|
| Email | Один или несколько адресов через запятую. Письма идут через почтовый сервер панели ([Настройка](Configuration.md)). |
| Telegram | Chat ID пользователя, группы или канала, куда бот может писать. Токен бота: свой у канала или пусто — тогда берётся из настроек панели. |
| Discord | Webhook URL канала Discord (**Настройки канала → Интеграция → Вебхуки**). Сообщения приходят как embed. |
| Личное сообщение в Discord | ID пользователя Discord (режим разработчика → правый клик → «Копировать ID»). Пишет Discord-бот панели; у пользователя должен быть общий сервер с ботом. |
| Webhook | Ваш URL и секрет подписи. Панель отправляет JSON (см. ниже). |

Токены, адреса вебхуков и секреты хранятся зашифрованно и больше не показываются: оставьте поле
пустым, чтобы сохранить прежнее значение. Выключенный канал не получает ничего, кроме тестового
сообщения.

Адреса вебхуков и Discord должны вести на публичный адрес. Адрес в частной сети (`127.0.0.1`,
`10.0.0.0/8`, `192.168.0.0/16`, `169.254.169.254` и подобные, в том числе за именем хоста)
отклоняется при сохранении канала и проверяется снова при каждой отправке; перенаправления не
выполняются. Для приёмника в вашей собственной сети включите **Настройки → Интеграции →
Уведомления в частные сети**.

**Отправить тест** сразу отправляет в канал тестовое сообщение; результат — в журнале.

## События и маршруты

На странице канала отметьте события, которые он должен получать. В списке каналов видно, какие
каналы слышат каждое событие.

| Событие | `event` | `data` |
|---|---|---|
| Сервер недоступен | `server_down` | `server`, `host`, `last_seen` |
| Достигнут лимит | `limit_reached` | `user`, `reason` (`traffic`, `total_traffic`, `expired`) |
| Доступ скоро закончится | `access_expiring` | `user`, `until` (дата) |
| Ключи нужно импортировать заново | `keys_changed` | `user`, `server` |
| Ключи отозваны | `keys_revoked` | `user`, `server` |
| Ключи переведены на AmneziaWG 3.1 | `keys_moved` | `user`, `server` |
| Заявка на регистрацию | `registration_pending` | `user`, `email` |
| Новое обращение в поддержку | `ticket_created` | `user`, `type`, `subject` |
| Сообщение в чате | `chat_message` | `user`, `text`, `count` |
| Открыт инцидент | `incident_opened` | `server`, `reports` |
| Инцидент закрыт | `incident_closed` | `server` |
| Новое предложение статьи | `suggestion_created` | `user`, `kind`, `title` |
| Оплата получена | `payment_received` | `user`, `plan`, `amount`, `currency`, `provider` |
| Ретранслятор переключился | `relay_switched` | `group`, `relay`, `from`, `to` |
| Сервер группы недоступен с ретранслятора | `member_unreachable` | `group`, `relay`, `server` |
| Ни один сервер группы не доступен | `group_unreachable` | `group`, `relay` |
| Ретранслятор не отвечает | `relay_down` | `relay`, `host`, `last_seen` |
| Сервер группы отстаёт | `member_lagging` | `group`, `server`, `since` |

Уведомления о пользователе уходят туда, что он выбрал на странице **Мессенджеры**: по умолчанию
на email или в привязанный Telegram или Discord ([Telegram и Discord](Messengers.md)).
Сами пользователи получают письмо о достигнутом лимите и за три дня до конца доступа, если у них
указан адрес. Когда инцидент закрыт, все сообщившие о нём получают письмо, что сервер снова
работает (`incident_resolved`; оно уходит только пользователям, не в каналы).

Ответ поддержки приходит туда, откуда пользователь писал последним: если из бота — сам ответ
уходит в этот мессенджер, даже без email (`chat_answer`, `request_answer`), если с сайта — ждёт
на сайте. Если за 2 минуты пользователь не ответил и не прочитал ответ в панели, туда, что он
выбрал, уходит одно напоминание со ссылкой на переписку, без текста ответа, только
пользователю: «в чате поддержки новое сообщение» для чата (`support_answer`, данные `user`, `url`)
или «на ваше обращение пришёл новый ответ: тема» для обращения (`request_reminder`, данные `user`,
`topic`, `url`). Если сам ответ уже дошёл до этого канала, напоминания нет; ответ, который
мессенджер не принял (бот заблокирован), не считается. Несколько ответов подряд дают одно
напоминание, пока пользователь не напишет. Если выбранный канал недоступен (мессенджер не
привязан, у бота нет токена, бот заблокирован, Discord не принимает личные сообщения, письмо не
ушло), напоминание пробует остальные по очереди — Telegram, Discord, email — кроме канала, куда
дошёл ответ, и останавливается на первом, который его принял; в журнале доставки видны ошибки всех опробованных. См.
[Обращения](Support-and-incidents.md).
 Когда обращение ждёт пользователя, решено или закрыто, пользователь узнаёт об этом там, что выбрал (`request_status`; в мессенджер его последнего сообщения в обращении, если оно оттуда). Эти события уходят только пользователю. Так же — решения по предложенной пользователем статье: `suggestion_accepted` (со ссылкой на опубликованную страницу) и `suggestion_rejected` (с причиной), см. [Инструкции](Guides-and-releases.md).

Каждое сообщение пишется на языке того, кто его читает. Язык своих уведомлений пользователь
выбирает на странице **Мессенджеры**; пока не выбрал — получает язык сайта (русский). Каналы
всегда получают язык сайта, о ком бы ни было событие. Переключатель RU/EN в шапке панели
меняет и этот язык. `data` вебхука от языка не зависит: слова панели в нём (`type` обращения) —
на английском, а коды (`reason` лимита) остаются кодами; в сообщении они написаны словами:
«трафик за период израсходован», «весь трафик израсходован», «срок доступа закончился».

Сообщения в чате, которые пользователь отправил в течение двух минут, дают одно уведомление.
Оно уходит через две минуты после первого сообщения, каждое сообщение — отдельной строкой
в `text`; `count` в `data` говорит, сколько их.

О сервере, который перестал отвечать, сообщается один раз; повторно — только после того, как он
вернулся и снова пропал.

## Доставка и журнал

Сообщения отправляются в фоне. В каждый канал — отдельно: канал с ошибкой не задерживает
остальные. Временная ошибка (нет соединения, таймаут, HTTP 408, 425, 429 или 5xx) повторяется с
растущей паузой 30 секунд, затем 1, 2 и 4 минуты: всего 5 попыток. Остальные ошибки — сразу отказ.

**Журнал** показывает каждую доставку: время, событие, канал, статус, попытки и ошибку. Одно
событие никогда не доставляется в один канал дважды. Доставка, оставшаяся в «Отправляется» после
остановки воркера, через 10 минут отправляется снова или, если попытки кончились, получает отказ.
Отправленные и неудавшиеся доставки удаляются через `LAMNEZIA_NOTIFICATION_RETENTION_DAYS` дней
(по умолчанию 90).
