# Настройка ботов

По шагам с нуля до работающего Telegram-бота, Discord-бота и канала Discord с уведомлениями для
администраторов. Что боты умеют для пользователей — в разделе [Telegram и Discord](Messengers.md).

Оба бота необязательны и не зависят друг от друга: можно настроить один, другой или оба.

## 1. Telegram-бот

1. Откройте в Telegram [@BotFather](https://t.me/BotFather) и отправьте `/newbot`.
2. Введите отображаемое имя (`Мой VPN`) и username, оканчивающийся на `bot` (`my_vpn_bot`).
3. BotFather пришлёт токен вида `123456789:AA…`. Храните его в секрете: у кого токен, тот управляет
   ботом. Утёкший токен заменяется командой `/revoke`.
4. По желанию, для **Входа через Telegram** на странице входа: отправьте `/setdomain`, выберите бота
   и введите домен панели (`vpn.example.com`, без `https://`).

Меню команд и описания бот задаёт сам; больше в BotFather ничего не нужно.

## 2. Приложение и бот Discord

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications) и нажмите
   **New Application**; назовите его как бота.
2. **General Information**: скопируйте **Application ID**.
3. **OAuth2**: нажмите **Reset Secret** и скопируйте **Client Secret**. В **Redirects** добавьте
   `<адрес панели>/accounts/discord/callback/`, например
   `https://vpn.example.com/accounts/discord/callback/`. Точный адрес панель показывает под полями
   Discord в настройках. Он должен совпадать символ в символ, включая `https` и `/` в конце.
4. **Bot**: нажмите **Reset Token** и скопируйте токен. **Privileged Gateway Intents** оставьте
   выключенными: боту они не нужны. **Public Bot** можно выключить, чтобы пригласить бота могли
   только вы.
5. Пригласите бота на свой сервер: **OAuth2 → URL Generator**, scopes `bot` и
   `applications.commands`, права бота не нужны. Откройте полученную ссылку и выберите сервер.

Личные сообщения от бота приходят только тем, у кого с ним есть общий сервер, поэтому приглашайте
его на сервер, где есть ваши пользователи.

Application ID и client secret нужны для привязки и входа через Discord, токен бота — для самого
бота. Привязка командой `/link <код>` работает и только с токеном бота.

## 3. Токены в панели

**Настройки → Интеграции** (администраторы):

| Поле | Значение |
|---|---|
| Токен Telegram-бота | Токен от BotFather. |
| Имя Telegram-бота | Username, без `@`. |
| ID приложения Discord | **Application ID** из шага 2. |
| Секрет клиента Discord | **Client Secret** из шага 2. |
| Токен Discord-бота | Токен со страницы **Bot**. |

Сохраните. Токены и секрет хранятся зашифрованными и больше не показываются: пустое поле оставляет
сохранённое значение. **Вход через Telegram** и **Вход через Discord** по умолчанию выключены;
включите их здесь, если нужно.

## 4. Сервис ботов

Боты работают в сервисе `bots` из `compose.yaml`; профиль ему не нужен, он запускается вместе с
панелью. После обновления или если он не запущен:

```sh
docker compose up -d bots
docker compose logs -f bots
```

Новый или изменённый токен подхватывается за несколько секунд, без перезапуска. Под формой
настроек в блоке **Боты** оба бота должны быть в состоянии **работает**, с `@username`, а у
Discord — список серверов, где есть бот. **Нет токена** — поле пустое, **ошибка** показывает
причину (обычно неверный токен), **не отвечает** — контейнер `bots` остановлен или не достаёт до базы. Там же
кнопки **Выключить**, **Включить** и **Перезапустить**.

Проверка: откройте бота в Telegram и отправьте `/start` или выполните `/menu` на сервере Discord.
Discord-бот откроет панель в личных сообщениях, а на сервере ответит заметкой, которую видите только
вы; на сервере доступны лишь `/menu` и `/link`. Если личные сообщения закрыты, бот подскажет, как их
открыть в настройках конфиденциальности сервера. Непривязанному аккаунту бот предложит привязку;
привяжите его на странице **Мессенджеры** в профиле.

Обновления Telegram по умолчанию приходят через long polling: это работает за NAT и без домена.
Режим webhook для публичного HTTPS-домена — в разделе
[Telegram-бот](Messengers.md#telegram-бот).

## 5. Канал Discord для уведомлений администраторам

Уведомления в канал Discord идут через вебхук канала, бот для этого не нужен.

1. В Discord: **Настройки канала → Интеграция → Вебхуки → Новый вебхук**, выберите канал и нажмите
   **Копировать URL вебхука**.
2. В панели: **Админка → Уведомления** → добавьте канал типа **Discord** и вставьте URL.
3. Отметьте события, которые канал должен получать (сервер недоступен, новые обращения, сообщения в
   чате…), и сохраните.
4. **Отправить тест**: в канал должно прийти тестовое сообщение; результат — в журнале на той же
   странице.

Для одного администратора подойдёт и канал типа **Личное сообщение в Discord** с его ID
пользователя Discord: его отправляет Discord-бот панели. Чат Telegram настраивается так же, каналом
типа **Telegram**. См. [Уведомления](Notifications.md).

## 6. Команды для администраторов и модераторов

Привязанный администратор или модератор видит в меню бота **Администрирование** (или вводит
`/admin`):

- **Сводка по серверам**: в сети ли сервер, загрузка ЦП, памяти и диска, обслуживание и открытые
  инциденты.
- **Трафик за сегодня**: трафик с полуночи по часовому поясу панели, всего и по серверам.
- **Инциденты**: открытые инциденты с числом жалоб. **Взять** назначает вам открытые обращения
  инцидента и переводит новые в работу — пользователи узнают, что ими занялись. **Закрыть**
  закрывает инцидент и его обращения и уведомляет пользователей; как и на странице инцидентов,
  закрывает только администратор, после подтверждения. Модератору **Взять** назначает только
  обращения его пользователей, никому ещё не назначенные.

Чтобы ответить пользователю, ответьте (кнопка мессенджера **Ответить**) на уведомление бота о новом
обращении или сообщении в чате: текст уйдёт в это обращение или чат как ответ поддержки. Номер
стоит в заголовке уведомления, `№12`. Модератор отвечает только на обращения своих пользователей и видит только свои серверы и
инциденты ([зона модератора](Security.md)).

Пользователям без роли администратора или модератора на все эти команды бот отвечает «Это вам
недоступно.», а их ответы на сообщения бота — обычные сообщения.

## Если что-то не работает

- **Ссылка на Telegram открывает telegram.org**: в настройках не задан или неверен username бота.
- **Discord пишет «Invalid OAuth2 redirect_uri»**: redirect в Developer Portal отличается от
  адреса в настройках панели.
- **В Discord нет slash-команд**: подождите минуту после первого запуска и переоткройте Discord;
  проверьте, что в приглашении был scope `applications.commands`.
- **Пользователю не приходят личные сообщения от Discord-бота**: у него нет общего сервера с ботом
  или его настройки приватности запрещают сообщения от участников сервера.
