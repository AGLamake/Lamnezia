# Пользователи, тарифы и лимиты

Тариф — это одновременно тарифный план и группа: он определяет, какие серверы и протоколы
получают его пользователи и какие действуют лимиты. Тарифы — в разделе **Тарифы** админки
(`/plans/`, только администраторы).

## Тарифы

### Тариф

| Поле | Значение |
|---|---|
| Трафик за период | Сколько ГБ пользователь может потратить за период; длина периода в днях (по умолчанию 30). Пусто — без ограничения. |
| Трафик всего | ГБ за весь срок доступа. Пусто — без ограничения. |
| Ключей не больше | Сколько ключей может быть у пользователя. Пусто — без ограничения. |
| Скорость, Мбит/с | Скорость каждого ключа пользователя — отдельно на скачивание и на отдачу. Пусто — без ограничения. См. [ограничение скорости](#ограничение-скорости). |
| Доступ, дней | Срок со дня назначения тарифа. Пусто — без срока. |
| Серверы, протоколы | Где пользователь получает ключи. Ничего не выбрано — все. |
| Пробный | Отметка пробного тарифа. |
| Цена, валюта | С [плагином оплаты](Billing-plugins.md) тариф с ценой и валютой, кроме пробного, продаётся в портале. Без плагинов — только для сведения. |

1 ГБ здесь — 1024³ байт. Тариф, который есть у пользователей, удалить нельзя: сначала назначьте им другой.
Тариф, за который платили, остаётся в истории: чтобы снять его с продажи, очистите цену.

## Тариф пользователя

На странице **Тарифы** введите имя пользователя в блоке **Тариф пользователя**. Откроется
страница с лимитами, которые действуют для него сейчас; на ней меняются тариф и личные лимиты:

- личный лимит заменяет значение тарифа только для этого пользователя; пусто — как в тарифе;
- **Доступ до** заменяет дату окончания, которую даёт тариф;
- с новым тарифом срок доступа начинается заново, личные лимиты сохраняются.

Пользователь без тарифа не может получать ключи. Изменения тарифов и лимитов пишутся в
[журнал действий](Audit.md).

## Применение лимитов

Каждые `LAMNEZIA_TRAFFIC_INTERVAL` секунд (по умолчанию 5 минут) панель проверяет пользователей
с тарифом и отключает все их активные ключи — статус «отключён по лимиту», пир убирается
с сервера, адрес и ключи хранятся в панели, — если:

- истёк срок доступа;
- трафик с назначения тарифа достиг лимита «Трафик всего»;
- трафик за текущий период достиг лимита «Трафик за период».

Считается трафик в обе стороны по всем ключам пользователя, включая отозванные. Периоды идут
подряд со дня назначения тарифа; трафик учитывается по часам, поэтому час, в котором начался
период, относится к предыдущему.

Ключи, отключённые по лимиту, включаются сами, когда пользователь снова в пределах лимитов:
начался новый период, продлён срок («Доступ до»), назначен тариф или увеличен лимит. Ключи,
отключённые администратором вручную, панель сама не включает. Если включить вручную ключ
пользователя, который всё ещё за лимитом, при следующей проверке он отключится снова.

Пользователей без тарифа и ключи без владельца проверка не трогает. Отключения и включения
идут фоновыми операциями (видны в журнале операций) и пишутся в [журнал действий](Audit.md)
без автора.

## Ограничение скорости

Скорость ключа ограничивается на сервере, внутри контейнера протокола, по его адресу: `tc`
формирует скачивание на интерфейсе (HTB) и отбрасывает отдачу сверх лимита (policing). Каждый ключ
пользователя получает всю скорость, лимит между ключами не делится. Пользователи без лимита
скорости и ключи без владельца не ограничиваются. AmneziaWG, WireGuard и XRay (см.
[XRay](#ограничение-скорости-xray) ниже). Policing пропускает пакеты до 64 КБ, которые туннель склеивает из мелких, и сразу
пропускает десятую долю секунды на лимите (не меньше 128 КБ), так что лимит не режет отдачу
намного ниже своего значения.

Лимит применяется и снимается без перезапуска контейнера и без обрыва сессий других клиентов:

- сразу при сохранении скорости тарифа или пользователя либо тарифа пользователя;
- иначе каждые `LAMNEZIA_TRAFFIC_INTERVAL` секунд — так подхватываются выданные, включённые
  и отключённые ключи и массовая смена тарифа.

Панель трогает только сервер, где правила изменились, операцией **Применение ограничений
скорости** в журнале операций. Операция с ошибкой сама не повторяется: запустите её снова из
журнала, иначе новую запустит следующее изменение.

На сервере панель хранит правила в `lamnezia_speed.sh` рядом с конфигом протокола
(`/opt/amnezia/awg/` для AmneziaWG) и добавляет одну строку перед `tail -f /dev/null`
в `/opt/amnezia/start.sh`: она запускает правила после подъёма интерфейса, поэтому лимиты
сохраняются после перезапуска контейнера или сервера. Если в образе контейнера нет полного `tc`,
операция ставит `iproute2-tc` из пакетов Alpine (контейнеру один раз нужен интернет).

Переустановка протокола в приложении Amnezia пересоздаёт контейнер без этих файлов: лимиты
вернутся после следующего изменения лимитов или ключей либо при повторном запуске последней
операции.

### Ограничение скорости XRay

В XRay нет лимита скорости на клиента, а адрес клиента — это адрес его подключения, поэтому ключи
XRay ограничиваются иначе — в обе стороны, и TCP, и UDP:

- в `server.json` для каждого ключа с лимитом добавляется outbound `freedom` `lamnezia-<метка>`
  с меткой сокета и правило `routing`, которое направляет туда ключ (по его `email`). Остальные
  ключи идут через первый outbound по умолчанию; правила маршрутизации, уже записанные в файле,
  сохраняются и срабатывают первыми.
- `nftables` в контейнере отбрасывает трафик метки сверх лимита: исходящий — по метке, ответы —
  по метке соединения, скопированной с неё. Правила лежат в `/opt/amnezia/xray/lamnezia_speed.nft`
  (volume данных контейнера); операция ставит `nftables` из пакетов Alpine и добавляет одну строку
  сразу после `killall -KILL xray` в `/opt/amnezia/start.sh`, поэтому правила загружаются до
  запуска xray.

Новая скорость только перезагружает правила `nft`. Когда меняется набор ключей с лимитом, меняется
и `server.json`, и контейнер перезапускается: переподключаются все клиенты XRay на сервере.
Ограничивается трафик между xray и интернетом; клиент получает ту же скорость.

Когда приложение Amnezia пересоздаёт контейнер или переписывает `server.json`, маршруты, строка
запуска и блоки статистики пропадают. Сбор трафика тогда не получает статистику XRay, и следующий
запуск ограничений скорости применяет их снова вместе со статистикой. Операция завершается ошибкой,
если после неё не отвечает API статистики xray, и тогда сама не повторяется.

## Пользователи

Страница **Пользователи** в админке (`/users/`, администраторы и модераторы) — список всех, кто
зарегистрирован в панели, с тарифом, сроком доступа и числом активных ключей. Модератор видит и
меняет только своих пользователей ([зона модератора](Security.md#зона-модератора)).

### Фильтры

| Фильтр | Показывает |
|---|---|
| Имя или email | Пользователей, у которых имя или email содержит текст. |
| Тариф | Пользователей на тарифе или без тарифа. |
| Статус | Активные, ждущие подтверждения или заблокированные. |
| Сервер | Пользователей с ключом (не отозванным) на любом протоколе сервера. |

### Карточка пользователя

По клику на имя открывается карточка:

- **Тариф и лимиты** — значение в тарифе, личное значение и действующее для каждого лимита;
  **Изменить** открывает [тариф пользователя](#тариф-пользователя);
- **Трафик** — израсходовано за текущий период и с назначения тарифа;
- **Ключи** — все ключи пользователя со статусом и протоколом.

### Массовые действия

Отметьте пользователей в списке, выберите действие в **С отмеченными** и нажмите **Применить**:

| Действие | Что происходит |
|---|---|
| Продлить доступ | Добавляет дни к сроку доступа; истёкший срок считается от сегодня. Ключи, отключённые по сроку, включаются обратно. Пользователи без тарифа или с бессрочным доступом пропускаются. |
| Отключить ключи | Отключает все активные ключи вручную: лимиты их обратно не включат. Пользователи без активных ключей пропускаются. |
| Сменить тариф | Назначает тариф и начинает срок доступа заново; личные лимиты сохраняются. Ключи включаются или отключаются по новым лимитам. Пользователи, уже стоящие на этом тарифе, пропускаются. |
| Перевыпустить ключи | Каждому ключу пользователей — новый, старые перестают работать сразу. Это одна операция `keys.reissue` на протокол для всех пользователей. Пользователи без ключей или которым нельзя иметь ключи пропускаются. |

После действия открывается отчёт: по каждому пользователю — изменён он или пропущен и почему,
и какие операции с ключами запущены. Ключи меняются на серверах в фоне; отчёт обновляется сам,
пока не завершатся все операции. Операцию с ошибкой можно открыть и запустить снова.
Каждый изменённый пользователь пишется в [журнал действий](Audit.md) (`users.extend`,
`users.disable`, `users.change_plan`, `users.reissue`).
